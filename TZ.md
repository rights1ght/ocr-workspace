# ТЗ: локальное приложение OCR-воркспейс

Версия: 1.0 · Дата: 2026-11-02 · Статус: согласовано с заказчиком

Рабочее название продукта: **OCR Workspace**. UI и все тексты — на русском языке.

---

## 1. Цель и контекст

### 1.1 Проблема

Нужно превращать бумажные и PDF-документы в редактируемый текст с сохранением структуры (заголовки, списки, таблицы, формулы, картинки), а затем выгружать результат в Markdown или HTML. Существующие онлайн-сервисы требуют загрузки документов на чужой сервер, платят за страницы и часто ломают таблицы.

### 1.2 Решение

Локальное веб-приложение, работающее на одном компьютере заказчика. Документы не покидают машину. Пользователь перетаскивает файлы, получает распознанный документ в WYSIWYG-редакторе рядом с изображением оригинала, правит и выгружает в `.md` или `.html`.

### 1.3 Целевой результат (definition of success)

Десятистраничный скан проходит путь «загрузка → распознавание → правка → экспорт в Markdown» без ручного вмешательства в структуру, и полученный `.md` открывается в Obsidian с корректными заголовками, списками, таблицами и картинками.

### 1.4 Принципы

- **Локальность.** Ни одного сетевого запроса наружу во время работы, кроме первой загрузки модели и зависимостей.
- **Оригинал неприкосновенен.** Исходный файл никогда не изменяется и не перезаписывается.
- **Движок за интерфейсом.** OCR-движок подключается через внутренний адаптер; замена Surya на другую модель не должна затрагивать UI и API.
- **Деградация вместо падения.** Ошибка на одной странице или блоке не должна ломать весь документ.

### 1.5 Что НЕ является целью

- Замена Word/Google Docs и совместная работа над документами.
- Массовая оцифровка библиотек и корпоративный документооборот.
- Гарантированное распознавание рукописного русского текста.
- Облачный сервис, многопользовательский режим, мобильные приложения.

## 2. Целевая аудитория и роли

### 2.1 Пользователь

Один человек — владелец компьютера. Работает за десктопом или ноутбуком, технически подкован на уровне «умею запустить команду в терминале», но не обязан знать Python, Docker и llama.cpp.

### 2.2 Роли

| Роль | Описание | Права |
|---|---|---|
| Владелец (единственная роль) | Запускает приложение локально | Полный доступ: загрузка, правка, экспорт, удаление, настройки |
| Гость | Не предусмотрен | — |

### 2.3 Ограничения аудитории

- Интерфейс на русском, без переключателя языков (i18n не делаем, но все строки — в одном файле ресурсов).
- Авторизации нет: приложение слушает только `127.0.0.1`.
- Разрешение экрана от 1280×800; мобильная вёрстка не требуется.

## 3. Тип продукта и платформы

| Параметр | Значение |
|---|---|
| Тип | Локальное веб-приложение (SPA + локальный API-сервер) |
| Запуск | Скрипт-лаунчер из корня проекта, открывает браузер автоматически |
| ОС | Linux (основная, целевая). Windows/macOS — не гарантируются |
| Браузеры | Chrome/Chromium 120+, Firefox 120+ |
| Сеть | Только loopback `127.0.0.1:8765` |
| Интернет | Нужен один раз — скачать модель и зависимости; далее работа офлайн |
| Языки документов | Русский, английский, смешанный. Язык не выбирается вручную |

**FR-0.1.** Сервер обязан слушать только `127.0.0.1` (не `0.0.0.0`), порт по умолчанию 8765, переопределяется переменной окружения.

**FR-0.2.** Лаунчер обязан: проверить наличие окружения, при необходимости создать его, запустить llama-server при первом OCR-задании, запустить API, открыть браузер и корректно завершить все дочерние процессы по Ctrl+C.

## 5. Пользовательские сценарии и критерии приёмки

Формат: сценарий → шаги → критерии приёмки (проверяемые).

### US-1. Загрузка пакета файлов

Как владелец, я хочу перетащить сразу несколько файлов, чтобы не загружать их по одному.

- Перетаскивание в зону на главной странице принимает файлы, кнопка «Выбрать файлы» открывает системный диалог.
- Каждый файл становится отдельным документом со статусом «В очереди».
- Неподдерживаемый формат отклоняется с сообщением «Формат .xyz не поддерживается» и перечнем допустимых.
- Файл больше 200 МБ отклоняется с сообщением о лимите.
- Документ больше 200 страниц отклоняется с сообщением о лимите страниц.
- Дубликат (совпадение SHA-256 с уже загруженным файлом) помечается бейджем «Копия» и не создаёт второй документ без подтверждения.

**Критерий приёмки:** 20 файлов разных форматов загружаются одним действием; все появляются в библиотеке не позднее 2 с; каждый получает корректный статус.

### US-2. Распознавание скана

Как владелец, я хочу загрузить скан и получить редактируемый документ.

- PDF без текстового слоя рендерится в изображения (DPI из настроек, по умолчанию 150) и отправляется в Surya.
- Для каждой страницы сохраняются блоки с типом, координатами, уверенностью и HTML.
- Блоки собираются в документ в порядке `reading_order`.
- Прогресс обновляется не реже одного раза в 2 с.
- По завершении открывается редактор с готовым содержимым.

**Критерий приёмки:** 10-страничный скан обрабатывается без ошибок; в документе присутствуют все страницы; заголовки, абзацы и таблицы визуально соответствуют оригиналу; каждая страница имеет запись с числом блоков > 0.

### US-3. Цифровой PDF

Как владелец, я не хочу гонять OCR там, где текст уже есть.

- Если на странице извлекается ≥ 100 непробельных символов, страница считается цифровой и OCR для неё не запускается.
- Порядок блоков берётся из координат (сверху вниз, слева направо с учётом колонок).
- Заголовки определяются по размеру шрифта относительно медианы по документу.
- Таблицы распознаются табличным парсером; при неудаче таблица выводится как текст с сохранением строк.
- OCR запускается только для страниц без текстового слоя.

**Критерий приёмки:** цифровой PDF из 10 страниц обрабатывается быстрее, чем тот же PDF через OCR, и не содержит артефактов распознавания; смешанный PDF (5 цифровых + 5 сканов) обрабатывается корректно постранично.

### US-4. Импорт DOCX

Как владелец, я хочу открыть свой `.docx` и сразу выгрузить его в Markdown.

- DOCX конвертируется в семантический HTML: заголовки, списки, таблицы, ссылки, изображения.
- Форматирование, не выразимое в HTML (колонтитулы, поля, стили), отбрасывается без ошибки.
- Изображения сохраняются в `assets/` и вставляются в документ.
- OCR не запускается.

**Критерий приёмки:** DOCX с двумя таблицами и тремя изображениями открывается в редакторе с теми же таблицами и изображениями; экспорт в `.md` содержит таблицы GFM и ссылки на `assets/`.

### US-5. Правка документа

Как владелец, я хочу править текст как в Word.

- Все операции тулбара работают: заголовки, жирный/курсив/подчёркнутый/зачёркнутый, списки, цитата, код, ссылка, таблица, изображение, формула.
- Вставка из буфера сохраняет только разрешённые теги (см. 7.5).
- Ctrl+Z / Ctrl+Shift+Z работают минимум на 50 шагов.
- Правки сохраняются автоматически; после перезагрузки страницы содержимое идентично.
- Индикатор показывает одно из состояний: «Изменено…», «Сохранение…», «Сохранено в 14:32».

**Критерий приёмки:** правка 5 разных типов блоков, перезагрузка вкладки — все изменения на месте; параллельная правка в двух вкладках не приводит к потере данных (побеждает последняя с предупреждением о конфликте по версии).

### US-6. Просмотр оригинала рядом

Как владелец, я хочу видеть скан, пока правлю текст.

- Панель оригинала показывает текущую страницу, синхронизированную со скроллом редактора.
- Клик по тексту в редакторе подсвечивает соответствующий прямоугольник на странице (жёлтая рамка).
- Клик по прямоугольнику прокручивает редактор к блоку.
- Есть миниатюры страниц и переход по ним.
- Зум 50–200 %, режим «по ширине».
- Переключатель «Показать разметку блоков» рисует все прямоугольники полупрозрачно.

**Критерий приёмки:** связка работает для документа из 10 страниц; подсветка появляется не позднее 150 мс после клика; при отсутствии геометрии для блока (после ручного редактирования) подсветка не ломает интерфейс.

### US-7. Правка типа блока

Как владелец, я хочу исправить «абзац», который на самом деле заголовок.

- При установке курсора в блок тулбар показывает текущий тип.
- Смена типа перестраивает блок (например, `Text → H2`) без потери текста.
- Для таблицы доступно преобразование «таблица → текст» и обратно только для простых случаев (без объединённых ячеек); при невозможности показывается предупреждение.

**Критерий приёмки:** смена типа у 10 блоков подряд не теряет ни одного символа; после экспорта тип отражён корректной разметкой.

### US-8. Экспорт Markdown

Как владелец, я хочу получить `.md`, который откроется в Obsidian.

- Заголовки → `#`/`##`/`###`, абзацы → пустая строка между ними.
- Жирный/курсив/зачёркнутый → `**`/`*`/`~~`; ссылки → `[текст](url)`.
- Списки → `-` с отступом 2 пробела на уровень; нумерованные → `1.`
- Таблицы → GFM pipe-таблицы; объединённые ячейки разворачиваются с повтором значения и пометкой в конце документа.
- Формулы → `$$…$$` для блочных и `$…$` для строчных (LaTeX как есть).
- Изображения → `![alt](assets/имя.png)`.
- Код → тройные обратные кавычки с языком, если он определён.
- Первая строка файла — YAML-заголовок с `title`, `source`, `created`, `pages`.
- При наличии изображений отдаётся ZIP: `<имя>.md` + `assets/`.

**Критерий приёмки:** экспортированный `.md` открывается в Obsidian без ошибок разметки; таблица из 4×5 ячеек отображается таблицей; формула рендерится; изображение отображается.

### US-9. Экспорт HTML

Как владелец, я хочу получить самодостаточный HTML.

- Один файл с инлайн-CSS, без внешних зависимостей и скриптов.
- Изображения либо встроены как base64 (опция «один файл», по умолчанию), либо лежат рядом в `assets/`.
- Формулы рендерятся KaTeX при наличии интернета; без интернета — как исходный LaTeX в `<span class="math">`.
- Разметка семантическая: `article`, `h1`–`h3`, `table`, `figure`.

**Критерий приёмки:** файл открывается в браузере без сети и выглядит как документ; в файле нет ссылок на внешние CDN в режиме «один файл».

### US-10. История и библиотека

Как владелец, я хочу вернуться к документу через неделю.

- Список сортируется по дате изменения (по умолчанию), доступна сортировка по имени и статусу.
- Фильтр по статусу: все / в очереди / обработка / готов / ошибка.
- Поиск по имени файла (подстрока, без учёта регистра).
- Карточка показывает: имя, тип источника, число страниц, статус, дату, длительность обработки.
- Удаление с подтверждением; удаляются БД-запись, оригинал, страницы, ассеты, экспорты.

**Критерий приёмки:** после перезапуска приложения все документы на месте с сохранёнными правками.

### US-11. Ошибки и восстановление

Как владелец, я хочу понимать, что пошло не так, и уметь повторить.

- Ошибка движка → статус «Ошибка», текст причины, кнопка «Повторить».
- Ошибка одной страницы → остальные страницы обрабатываются; страница помечается «Ошибка OCR», в документе остаётся плейсхолдер с изображением страницы.
- Нехватка памяти → сообщение с рекомендацией снизить DPI и закрыть приложения.
- Приложение не падает при повреждённом PDF: показывает «Файл повреждён или защищён паролем».
- Незавершённые задачи после перезапуска помечаются «Прервано» и могут быть перезапущены.

**Критерий приёмки:** принудительное убийство llama-server во время обработки даёт понятную ошибку и успешный повтор после перезапуска движка.

### US-12. Настройки

Как владелец, я хочу подстроить приложение под своё железо.

- DPI рендера: 96 / 150 / 192 / 300 (по умолчанию 150).
- Порог уверенности: 0.5–0.99 (по умолчанию 0.80).
- Каталог данных: смена с предупреждением о переносе.
- Размер шрифта редактора: 14–20 px (по умолчанию 16).
- Параллельные OCR-задачи: 1–2 (по умолчанию 1).
- Изменения применяются к новым задачам; для текущих — не действуют.

**Критерий приёмки:** смена DPI на 96 сокращает время обработки тестовой страницы не менее чем на 30 % без падения документа.

## 7. Данные и сущности

### 7.1 Хранилище

- СУБД: SQLite (режим WAL, `foreign_keys=ON`, `busy_timeout=5000`).
- Файлы: на диске в каталоге данных.
- Каталог по умолчанию: `./data` рядом с проектом, переопределяется `APP_DATA_DIR`.

Структура каталога:

```
data/
  app.db
  documents/<document_id>/original.<ext>
  documents/<document_id>/pages/0001.png
  documents/<document_id>/assets/img-p0001-01.png
  documents/<document_id>/exports/<name>.md
  documents/<document_id>/exports/assets/...
  logs/app.log
  models/                        # веса GGUF (если качаем вручную)
```

### 7.2 Сущности

**document** — документ.

| Поле | Тип | Описание |
|---|---|---|
| id | TEXT (uuid) | Первичный ключ |
| title | TEXT | Отображаемое имя (по умолчанию — имя файла без расширения) |
| original_filename | TEXT | Исходное имя |
| source_type | TEXT | `pdf_text` / `pdf_scan` / `pdf_mixed` / `image` / `docx` / `txt` |
| mime | TEXT | MIME-тип |
| size_bytes | INTEGER | Размер исходника |
| sha256 | TEXT | Хеш для поиска дубликатов |
| page_count | INTEGER | Число страниц |
| status | TEXT | `queued` / `processing` / `ready` / `error` / `canceled` / `interrupted` |
| engine | TEXT | `surya-2.5` / `pdf-text` / `docx` / `plain` |
| content_html | TEXT | Канонический HTML документа |
| content_version | INTEGER | Версия для оптимистичной блокировки |
| low_confidence | INTEGER | Число блоков ниже порога |
| error_message | TEXT | Текст последней ошибки |
| processing_ms | INTEGER | Длительность обработки |
| created_at / updated_at | TEXT (ISO 8601) | Даты |

**page** — страница.

| Поле | Тип | Описание |
|---|---|---|
| id | INTEGER | PK |
| document_id | TEXT | FK → document |
| page_no | INTEGER | 1-based |
| image_path | TEXT | Путь к PNG-рендеру |
| width / height | INTEGER | Пиксели |
| dpi | INTEGER | DPI рендера |
| has_text_layer | INTEGER | 1/0 |
| ocr_used | INTEGER | 1/0 |
| status | TEXT | `pending`/`done`/`error`/`skipped` |
| error_message | TEXT | Причина ошибки страницы |
| blocks_json | TEXT | Массив блоков (см. 7.3) |

**block** (внутри `blocks_json`) — не отдельная таблица; поля:

`id` (`b-<page>-<order>`), `order`, `type`, `label_raw`, `bbox` `[x0,y0,x1,y1]` в пикселях страницы, `polygon`, `html`, `confidence`, `skipped`, `error`, `edited` (bool).

**job** — задача обработки.

`id`, `document_id`, `type` (`process`/`reprocess_page`), `status` (`queued`/`running`/`done`/`error`/`canceled`), `progress` (0–100), `pages_done`, `pages_total`, `eta_seconds`, `started_at`, `finished_at`, `error_message`.

**export** — выгрузка.

`id`, `document_id`, `format` (`md`/`html`), `file_path`, `size_bytes`, `options_json`, `created_at`.

**setting** — ключ/значение (`key` TEXT PK, `value` TEXT JSON).

**app_event** — журнал для диагностики: `id`, `level`, `message`, `context_json`, `created_at`.

### 7.3 Контракт блока

- `bbox` — в пикселях изображения страницы, начало координат сверху слева.
- `order` — целое, порядок чтения.
- `type` — нормализованный тип из фиксированного списка: `Text`, `SectionHeader`, `SubHeader`, `List`, `Table`, `Equation`, `Caption`, `Footnote`, `Picture`, `Code`, `PageHeader`, `PageFooter`, `Form`, `TOC`, `Other`.
- `html` — фрагмент разрешённой разметки, без `<html>`, `<body>`, `<script>`.
- `confidence` — 0…1, средняя по токенам блока.

### 7.4 Правила сборки документа

1. Блоки сортируются по `order` внутри страницы; страницы — по `page_no`.
2. `PageHeader`/`PageFooter` по умолчанию **не попадают в тело**: сохраняются в метаданных страницы и доступны через переключатель в панели оригинала.
3. `SectionHeader` → `h2`, `SubHeader` → `h3`, первый заголовок документа → `h1` (определяется по максимальному размеру bbox среди заголовков).
4. `List` → `ul/ol` по эвристике маркеров в HTML блока.
5. `Table` → HTML таблицы как есть, с `clean_block_html`; объединённые ячейки сохраняются.
6. `Equation` → `<div class="math" data-latex="...">`.
7. `Picture` → `<figure><img src="assets/..."></figure>`, кроп по bbox с отступом 2 %.
8. `Caption` → `<figcaption>` внутри ближайшей фигуры, если она есть, иначе `<p class="caption">`.
9. `Code` → `<pre><code>`.
10. `Form` → таблица или список пар «поле — значение», если структура не распознана — `<div class="form">` с сохранённым HTML.
11. Каждый верхнеуровневый блок получает атрибуты `data-src-page` и `data-src-block` для связки с оригиналом.
12. Страницы разделяются `<hr data-page-break="N">`.

### 7.5 Санитайзинг HTML

- Разрешённые теги: `p, h1–h6, ul, ol, li, table, thead, tbody, tr, td, th, caption, colgroup, col, strong, em, b, i, u, s, code, pre, blockquote, a, img, figure, figcaption, hr, br, span, div, sub, sup, math, mrow, mi, mo, mn, msup, msub`.
- Разрешённые атрибуты: `href, src, alt, title, colspan, rowspan, class, data-*` из белого списка (`data-src-page`, `data-src-block`, `data-latex`, `data-page-break`, `data-kind`, `data-cs`, `data-rs`), `style` — только `text-align`.
- Запрещено: `script`, `iframe`, `object`, `embed`, `link`, `meta`, `on*`-атрибуты, `javascript:`-URL.
- Внешние ссылки получают `rel="noopener noreferrer"`.

### 7.6 Миграции и бэкапы

- Версия схемы в `PRAGMA user_version`; миграции — последовательные SQL-файлы, применяются при старте.
- Перед миграцией создаётся копия `app.db` в `data/backups/app-YYYYMMDD-HHMMSS.db`.
- Хранятся 5 последних бэкапов, старые удаляются.

### 7.7 Политика хранения

- Документы хранятся бессрочно, пока пользователь не удалит.
- Оригиналы не перезаписываются и не удаляются при повторной обработке.
- Экспортированные файлы удаляются вместе с документом.
- Временные файлы рендера складываются в `data/tmp` и очищаются при старте.

### 10.5 Безопасность

| ID | Требование |
|---|---|

| SEC-2 | Все пути к файлам строятся от `document_id` (UUID), а не от пользовательского имени; защита от `../` |
| SEC-3 | Загружаемые файлы проверяются по MIME и сигнатуре (magic bytes), а не только по расширению |
| SEC-4 | HTML санитайзится на входе и на выходе (см. 7.5) |
| SEC-5 | Экспорт HTML не содержит исполняемых скриптов и внешних ресурсов |
| SEC-6 | Логи не содержат полного текста документов, только имена файлов и размеры |
| SEC-7 | Нет сетевых исходящих запросов, кроме загрузки модели (проверяется тестом с заблокированной сетью) |

### 10.6 Персональные данные

Приложение обрабатывает документы пользователя локально. Согласие на обработку ПДн не требуется, поскольку данные не передаются третьим лицам. В README указано: при удалении документа удаляются все его файлы; при удалении каталога `data` данные исчезают полностью.

### 10.7 Логирование и диагностика

- Формат: `YYYY-MM-DD HH:MM:SS LEVEL module message key=value`.
- Уровни: DEBUG (только при `APP_DEBUG=1`), INFO, WARNING, ERROR.
- Файл `data/logs/app.log`, ротация при 10 МБ, хранится 3 файла.
- Каждая задача пишет: документ, страницы, длительность, DPI, движок, число блоков ниже порога.
- Эндпоинт `/api/diagnostics/logs?limit=200&level=`.

### 10.8 Конфигурация

Переменные окружения: `APP_DATA_DIR`, `APP_PORT` (8765), `APP_DEBUG`, `SURYA_MODEL_DIR`, `LLAMA_SERVER_BIN`, `LLAMA_PORT` (8181), `MAX_UPLOAD_MB` (200), `MAX_PAGES` (200), `OCR_DPI` (150).

### 10.9 Тестирование

- Backend: pytest, покрытие ключевых модулей pipeline ≥ 70 %.
- Обязательные тесты: детекция текстового слоя, сборка документа из блоков, санитайзер, конвертер md/html, экспорт ZIP, миграции, API-контракты.
- Frontend: Vitest + Testing Library для редактора и связки подсветки.
- E2E: Playwright — сценарии US-1, US-5, US-8 на подготовленных фикстурах.
- Фикстуры: 3 PDF (цифровой, скан, смешанный), 2 изображения, 1 DOCX, 1 TXT, 1 повреждённый файл.

## 12. Этапы и порядок реализации

### Этап 0. Spike (0.5–1 день) — обязательный

Цель: получить факты до написания кода приложения.

1. Окружение: `uv`, Python 3.12, `surya-ocr`, `llama.cpp`, GGUF Q8_0.
2. Прогон 20–30 реальных документов заказчика (сканы, фото, цифровые PDF, таблицы).
3. Замеры: время на страницу при 96/150/192 DPI, пиковая RAM, число блоков ниже 0.8.
4. Качественная оценка: CER на 5 страницах по 500 символов вручную; доля корректных таблиц.
5. Отчёт `spike-report.md`: цифры, скриншоты, решение — Surya 2.5 / Surya 2 / другой движок, выбранное квантование и DPI.

**Выход:** подтверждённые NFR-6/NFR-7, зафиксированные версии зависимостей, решение по Q-1…Q-6.

### Этап 1. Каркас и импорт (4–5 дней)

- Структура проекта, конфиг, логирование, миграции, каталог данных.
- API: загрузка, список, карточка, удаление, SSE-прогресс.
- Pipeline: детекция типа, рендер PDF, извлечение текста, DOCX, TXT.
- Сборка HTML документа, санитайзер.
- Библиотека (список + загрузка) и экран обработки.
- Тесты pipeline и API.

**Готово, когда:** PDF/скан/DOCX/TXT загружаются и превращаются в документ; библиотека работает; прогресс виден.

### Этап 2. OCR и редактор (5–7 дней)

- Адаптер `SuryaLocalEngine`, менеджер llama-server, обработка ошибок и таймаутов.
- Очередь, отмена, повтор, восстановление после перезапуска.
- Редактор TipTap: расширения, тулбар, автосохранение, версии.
- Просмотр оригинала: рендер, зум, миниатюры, связка блоков.
- Правка типа блока, подсветка низкой уверенности.

**Готово, когда:** 10-страничный скан можно распознать, отредактировать и увидеть связку с оригиналом.

### Этап 3. Экспорт и полировка (3–4 дня)

- Конвертеры md/html, ZIP-упаковка, модальное окно экспорта.
- Настройки, диагностика, горячие клавиши, пустые состояния, ошибки.
- Тёмная тема — вне MVP.
- Доступность, адаптивность 1024+, тосты, подтверждения.

**Готово, когда:** экспорт в md открывается в Obsidian, html — в браузере офлайн.

### Этап 4. Стабилизация (2–3 дня)

- E2E Playwright, прогон по чек-листу приёмки.
- README: установка, запуск, ограничения, лицензии.
- Лаунчер `run.sh`, проверка чистого запуска на чистой машине.
- Профилирование памяти и времени, исправление узких мест.

**Итого:** 15–21 рабочий день после spike.

## Приложение B. Правила экспорта: соответствие HTML → Markdown

| HTML | Markdown |
|---|---|
| `h1`…`h3` | `#`…`###` |
| `p` | абзац + пустая строка |
| `strong`/`b` | `**текст**` |
| `em`/`i` | `*текст*` |
| `s`/`del` | `~~текст~~` |
| `a[href]` | `[текст](href)` |
| `ul > li` | `- текст` (отступ 2 пробела на уровень) |
| `ol > li` | `1. текст` |
| `blockquote` | `> текст` |
| `pre > code` | ``` + язык + содержимое + ``` |
| `table` | GFM pipe-таблица; `colspan`/`rowspan` разворачиваются |
| `div.math[data-latex]`, `span.math[data-latex]` | `$$…$$` / `$…$` |
| `img[src]` | `![alt](относительный путь)` |
| `figure`/`figcaption` | изображение + курсивная подпись |
| `hr[data-page-break]` | `---` |
| прочие `div` | содержимое без обёртки |

## Приложение C. Чек-лист ручной приёмки

1. Загрузить 3 файла разом: цифровой PDF, скан PDF, DOCX.
2. Убедиться, что цифровой PDF обработан без OCR, скан — с OCR, DOCX — без OCR.
3. Дождаться завершения, открыть скан.
4. Проверить: заголовки, абзацы, одна таблица, одна картинка.
5. Кликнуть по абзацу — подсветился блок на странице; кликнуть по блоку на странице — редактор прокрутился.
6. Поменять тип одного блока на H2, исправить опечатку.
7. Перезагрузить вкладку — правки на месте.
8. Экспортировать в Markdown (с картинками) — скачался ZIP.
9. Открыть `.md` в Obsidian: структура и картинка корректны.
10. Экспортировать HTML «одним файлом», открыть без сети — выглядит как документ.
11. Перезапустить приложение — документы и правки на месте.
12. Удалить документ — каталог `data/documents/<id>` исчез.
13. Отключить сеть, повторить шаги 1–10.
